# 🚑 dsh-vision-router 崩溃处理手册

> 给 DSH 装"眼睛"的插件(视觉路由)。本手册在**插件导致 DSH 崩溃或无法启动**时使用。
> 适用环境:桌面版 / Web 版 DSH,profile = `web`(路径:`C:\Users\<你的用户名>\.dsh\profiles\web`)
> 路径说明:手册中的 `<你的用户名>` 请替换为你电脑的用户名(Windows 打开 cmd 运行 `echo %USERNAME%` 可查)。

---

## 一、先说最重要的事:崩溃了别慌,按顺序做

**铁律:先杀进程,再改文件,最后重启。**

插件装错/配错最坏的结果就是 DSH 起不来,恢复方法永远只有一条主线:

```
杀进程 → 诊断(doctor)→ 修复(repair)→ 手动兜底(改 package.json)→ 重启验证
```

**本插件自带医生**:`npx dsh-vision-router doctor / repair`,不需要 DSH 能启动就能运行,专门治"profile 文件坏了导致 DSH 起不来"的病。**优先用它,不要自己瞎改 JSON。**

## 二、症状速查表(对照你的报错找方案)

| # | 症状/报错 | 原因 | 处理(按顺序) |
|---|----------|------|-------------|
| 1 | 启动即退出,报 `SyntaxError: Unexpected token ... is not valid JSON` | profile 的 `package.json` 被存成了 **UTF-8 带 BOM**(文件开头多了不可见字符 `\uFEFF`) | ① `npx dsh-vision-router repair --profile web`(自动去 BOM 并验证)<br>② 仍失败 → 手动方案(见第三节 C) |
| 2 | 启动报 `duplicate loader entry id: vision-router` | 旧版手动 `cordis.patch.yml` 残留行与新版 bundle 补丁**重复注册** | ① 打开 `C:\Users\<你的用户名>\.dsh\profiles\web\cordis.patch.yml`(若存在),删除其中的 `vision-router` 行<br>② 重启 |
| 3 | 启动报 `configurable provider "deepseek-official" is already declared` | 插件版本过旧(v1.4.1 及更早)或与宿主 provider 冲突 | ① 安装 v1.4.2+ 版本<br>② 仍冲突 → 卸载插件(见第四节) |
| 4 | 启动报 `invalid plugin, expect function or object with an "apply" method, received object` | 插件文件被**写入一半**时 dsh 读取了它(文件竞态)——通常发生在运行期间改插件源码/装插件时重启 | ① 杀干净所有 DSH 进程<br>② 等 5 秒<br>③ 重启<br>④ 若反复出现 → 卸载重装(见第四节) |
| 5 | 服务器启动超时 / 端口打不开 | `package.json` 有**语法错误**(最常见:删行留下尾逗号) | ① 用 JSON 校验工具(或让 AI)检查 `package.json`<br>② 修复语法<br>③ 重启(注意:删行必须删掉前面的逗号) |
| 6 | 装完插件**不生效**(日志显示 `downloaded 0` / `added 0`) | pnpm v11 会静默拦截**发布不足 24 小时**的新版本 | ① 显式安装版本号:`dsh plugin --profile web add dsh-vision-router@<版本号>`<br>② 或等 24 小时后再装 |
| 7 | 图片识别不工作,报"当前模型不支持图片" | **不是崩溃**:插件故意不修改原模型组,你还在用纯文本路由 | 聊天页右下角切换到「**+ 自动识图**」模型组(插件会自动创建同名入口) |

## 三、通用恢复流程(逐步操作)

### A. 杀干净所有 DSH 进程

> **为什么**:残留进程会占用端口/锁文件,导致"杀不干净 → 重启失败"的假象。之前挂件事故就是多个 DeepSeek.exe 残留。

任务管理器 → 结束所有 **DeepSeek.exe** 和多余的 **node.exe** 进程(注意:node 里可能有别的程序,只杀 DSH 相关的;拿不准就先全杀,DSH 重启会自动拉起)。

命令行方式(管理员 PowerShell):

```powershell
Get-Process -Name 'DeepSeek','node' -ErrorAction SilentlyContinue | Stop-Process -Force
```

### B. 诊断 + 自动修复(插件自带医生)

```powershell
# 诊断:扫描 profile,报告 BOM、JSON 合法性、插件是否在依赖/bundle 里
npx dsh-vision-router doctor --profile web

# 修复:自动删除 package.json 开头的 BOM 字节并重新验证 JSON
npx dsh-vision-router repair --profile web
```

> doctor 只报告不改文件;repair 只删 BOM、不猜不改其他 JSON 内容。**先 doctor 后 repair**。

### C. 手动兜底:检查/修复 package.json

正确的位置:`C:\Users\<你的用户名>\.dsh\profiles\web\package.json`

**检查三件事**:

1. **有没有 BOM**:用 VS Code 打开 → 右下角显示"UTF-8 with BOM"就是有 → 点它 → "通过编码保存" → 选 `UTF-8`(无 BOM)。或交给 AI 用无 BOM 方式重写。
2. **JSON 语法对不对**:删行时是否留下了尾逗号?看 `dependencies` 和 `dsh.profile.bundles` 的最后一项后面有没有多余的逗号。
3. **插件条目是否齐全/多余**:正常安装后应同时存在两处——
   - `dependencies` 里有 `"dsh-vision-router": "..."`(或 `link:` 形式)
   - `dsh.profile.bundles` 数组里有 `"dsh-vision-router"`

### D. 重启并验证

```powershell
# 重启桌面版或:
dsh web
```

验证插件是否加载:

```powershell
dsh --profile web --dump-config | Select-String vision-router
```

能看到 `vision-router` 行 = 加载成功。

## 四、彻底卸载(插件反复搞崩 DSH 时的最终手段)

```powershell
# 官方卸载(推荐):
dsh plugin --profile web remove dsh-vision-router
```

官方命令不生效时,手动三连删:

1. 打开 `C:\Users\<你的用户名>\.dsh\profiles\web\package.json`,从 **`dependencies`** 中删除 `dsh-vision-router` 条目,**同时从 `dsh.profile.bundles` 数组中删除对应行**(两处都要删!只删一处会留幽灵引用)
2. 若存在 `C:\Users\<你的用户名>\.dsh\profiles\web\cordis.patch.yml`,删除其中 `vision-router` 行
3. 清理残留依赖(可选,释放空间):`Remove-Item -Recurse -Force C:\Users\<你的用户名>\.dsh\profiles\web\node_modules\sharp, C:\Users\<你的用户名>\.dsh\profiles\web\node_modules\@img`

> ⚠️ 手动改 JSON 三条铁律:
> 1. 保存必须用**无 BOM** 的 UTF-8(最保险:交给 AI 重写,或 VS Code 选"UTF-8")
> 2. **删行必须删尾逗号**(上一项末尾的逗号要一并删掉)
> 3. 改完**先验证再重启**:确认文件首字节是 `{`,不是 `\uFEFF`

## 五、预防铁律(避免再踩坑)

1. **运行期间不要改插件源码/配置**——dsh 可能读到写了一半的文件,直接 `invalid plugin`(症状 #4)
2. **重启前先杀干净所有 DSH 进程**(症状 #4/#5 的主要诱因)
3. **装新插件/升级用官方命令**,不要手动混用 `cordis.patch.yml` 和 bundle 管理(症状 #2)
4. **装完插件先别急着改配置**——先重启一次确认能正常启动,再进设置里调
5. **每次改 `package.json` 前备份一份**(复制成 `package.json.bak`)
6. 插件升级时注意 pnpm 的 24 小时静默拦截(症状 #6),报"没装上"先看这个
